## 0. 概要

| 項目 | 内容 |
|---|---|
| 目的 | 習慣化を可視化する。決めたことをやったらスタンプを押し、累計日数と連続回数を見せ、節目で褒める |
| 共有 | 友達とルームを作り、同じ習慣に一緒に取り組める |
| 対象ユーザー | 開発者本人と友達数人（一般公開しない） |
| 対象端末 | スマホのブラウザ（iOS Safari / Android Chrome）。PWAとしてホーム画面に追加できる |
| UI言語 | 日本語のみ |
| 状態 | フェーズ1（個人機能）とフェーズ2（ルーム機能）を実装済み。本番環境への公開は未実施 |

## 1. 用語

| 用語 | 英語識別子 | 定義 |
|---|---|---|
| 習慣 | habit | ユーザーが続けたいこと。個人の習慣とルームの習慣がある |
| 実施日 | scheduled day | 習慣の曜日設定に含まれる曜日に当たる日 |
| スタンプ | stamp | ある日に習慣をやったという記録。1習慣・1日につき最大1個 |
| 後押し | late stamp | 今日以外の日（過去7日以内）に押したスタンプ。`is_late = true` |
| 今日 | app today | 日本時間の午前3時で切り替わる日付（DATE-01 参照） |
| 累計 | total | スタンプがある日の数 |
| 現在の連続 | current streak | 実施日だけを数えた、途切れていないスタンプの回数 |
| 最長連続 | longest streak | 全期間での連続の最大値 |
| ルーム | room | 友達と1つの習慣に取り組むグループ。1ルーム1習慣 |
| オーナー | owner | ルームの管理者。最初は作成者 |
| メンバー | member | ルームに参加中の人（オーナーを含む） |
| 全員達成 | all-done day | その日が実施日のメンバー全員がスタンプを押した日 |
| アーカイブ | archived | 記録を残したまま閲覧専用にした習慣 |

## 2. 日付のルール

- **DATE-01** [確定] 1日の区切りは午前3時。日本時間の 0:00〜2:59 は前日として扱う。
- **DATE-02** [暫定] タイムゾーンは Asia/Tokyo に固定する（ユーザーごとのタイムゾーン設定はない）。
- **DATE-03** 日付は `YYYY-MM-DD` 形式で扱う。曜日は `0 = 日曜 〜 6 = 土曜`。
- **DATE-04** 「今日」は、サーバー（DB関数 `app_today()`）とクライアント（`appToday()`）が同じ式で計算する：`(現在時刻を日本時間にしたもの − 3時間) の日付`。

## 3. 認証・プロフィール

- **AUTH-01** [確定] Googleログインが必須。未ログインのときは、ログイン画面以外のすべてのページがログイン画面へリダイレクトする。
- **AUTH-02** ログイン画面へリダイレクトするときは元のパスを `next` に入れ、ログイン後にそこへ戻す。`next` はアプリ内のパス（`/` で始まり `//` で始まらない）だけを受け付ける。
- **AUTH-03** [確定] 初回ログイン時に表示名を登録する。初期値はGoogleアカウントの名前。設定画面から後で変更できる。
- **AUTH-04** 表示名は1〜30文字。
- **AUTH-05** [確定] アカウントの削除機能は作らない。

## 4. 習慣

- **HABIT-01** [確定] アーカイブしていない習慣は1人10個まで。ルームの習慣も数える。上限はDBで強制する。
- **HABIT-02** 設定項目：
  - 名前：必須、1〜30文字
  - 実施する曜日 [確定]：1つ以上
  - アイコン [暫定]：16種類の絵文字から選ぶ
  - 色 [暫定]：`orange` / `rose` / `violet` / `sky` / `emerald` / `amber`
- **HABIT-03** [確定] 曜日を変更すると、**今日以降にだけ**新しい設定が適用される。過去の日は当時の設定で実施日を判定する。曜日設定は履歴として保存する（`habit_schedules`）。
- **HABIT-04** ある日が実施日かどうかは、`valid_from <= その日` のうち `valid_from` が最も新しい曜日設定で判定する。
- **HABIT-05** 習慣の開始日（`start_date`）は作成日。ルームの習慣は参加日。作成後は変更できない。
- **HABIT-06** [暫定] アーカイブ：記録を残して閲覧専用にする。10個の上限に数えない。アーカイブから戻せる（上限に空きが必要）。
- **HABIT-07** 削除：記録ごと完全に消す。確認ダイアログを出す。

## 5. スタンプ

- **STAMP-01** 1習慣・1日につき最大1個。
- **STAMP-02** [確定] 押せる日は「今日」と「過去7日以内」。つまり `今日 − 7日 ≤ 日付 ≤ 今日`。
- **STAMP-03** [確定] 実施日でない日にも押せる。
- **STAMP-04** 押せない日：未来の日、開始日より前の日、8日以上前の日。アーカイブした習慣にも押せない。
- **STAMP-05** 取り消しは、押せる期間内（STAMP-02）ならできる。
- **STAMP-06** `is_late`（後押しかどうか）と `stamped_at`（押した日時）はサーバーが決める。クライアントから指定させない。
- **STAMP-07** [確定] 後押しのスタンプは、当日に押したものより薄く表示する。
- **STAMP-08** STAMP-02〜05 は、画面だけでなくDB（行単位アクセス制御）でも強制する。

## 6. 累計・連続の計算

- **STAT-01** 表示する数字は3つ：累計・現在の連続・最長連続。
- **STAT-02** 集計値はDBに保存しない。表示のたびにスタンプの一覧から計算する。
- **STAT-03** [確定] 連続は**実施日だけ**を数える。表示は「◯回連続」。
- **STAT-04** [確定] 実施日でない日のスタンプは累計にだけ数える。連続は伸びも途切れもしない。
- **STAT-05** [確定] 今日が実施日でまだ押していない場合は「途中」とみなし、連続を途切れさせない。
- **STAT-06** [確定] 過去の実施日に押し忘れがあれば、その時点で連続は途切れる。後押しで埋めれば復活する。

計算のしかた（`src/lib/habit-stats.ts` の `computeStats`）：

```
入力: start_date, schedules, stampDates（スタンプがある日付の集合）, today

total = start_date 以上 today 以下の stampDates の数

longest = 0; run = 0
for d in start_date .. today:
    if 実施日ではない(d): continue
    if d in stampDates: run += 1; longest = max(longest, run)
    elif d != today: run = 0

current = 0
for d in today .. start_date（過去に向かって）:
    if 実施日ではない(d): continue
    if d in stampDates: current += 1
    elif d == today: continue      # 今日は途中扱い
    else: break
```

例（月・水・金の習慣。今日は金曜でまだ押していない）：

| | 月 | 火 | 水 | 木 | 金（今日） |
|---|---|---|---|---|---|
| 実施日 | ○ | – | ○ | – | ○ |
| スタンプ | ✅ | ✅ | ✅ | | 未 |

→ 累計 3（火曜も数える）、現在の連続 2、最長連続 2

## 7. 褒める機能

- **PRAISE-01** [確定] スタンプを押すたびにメッセージを出す。取り消したときは出さない。
- **PRAISE-02** [確定] メッセージはアプリ内の定型文から選ぶ。AIでは生成しない。
- **PRAISE-03** [確定] 節目では紙吹雪の演出とともに専用メッセージを出す。
  - 連続の節目：3, 7, 14, 30, 50, 100回。100回より後は100の倍数ごと
  - 累計の節目 [暫定]：10, 30, 50, 100, 200, 365日。365日より後は100の倍数ごと（400, 500, …）
- **PRAISE-04** 押したときに出すメッセージは、次のうち最初に当てはまるもの：
  1. 押す前から押した後の間に、連続の節目を越えた → 越えた中で最大の節目のメッセージ（紙吹雪あり）
  2. 累計の節目を越えた → 累計の節目のメッセージ（紙吹雪あり）
  3. 後押しで、連続が2以上増えた → 「連続復活！」（紙吹雪あり）
  4. 再開した（PRAISE-05） → 「おかえり！」（紙吹雪なし）
  5. それ以外 → 定型文からランダムに1つ（紙吹雪なし）
- **PRAISE-05** [暫定] 「再開」とは、押した日より前にスタンプがあり、かつ押した日の直前の実施日7回がすべて未スタンプの場合。

## 8. 画面表示（個人）

- **UI-01** ホーム：アーカイブしていない自分の習慣（個人とルームの両方）を並べる。
  - 各習慣に表示するもの：アイコン、名前、曜日、現在の連続、累計、今日のスタンプボタン
  - ルームの習慣には「👥 ルーム」の印を付ける
  - 今日が実施日でない習慣には「今日はお休み」と表示する。押すことはできる
- **UI-02** [確定] 習慣の詳細：累計・現在の連続・最長連続と、月カレンダーを表示する。
  - カレンダーは日曜始まり。前後の月に移動できる（開始月から今月まで）
  - 見分けられるようにするもの：実施日、スタンプ、後押しのスタンプ（薄い）、押し忘れ（過去の実施日で未スタンプ）、もらった👏の数
  - 押せる日（STAMP-02）はタップでスタンプを押したり取り消したりできる
- **UI-03** スタンプは、サーバーの応答を待たずに画面に反映する。保存に失敗したらその日だけ元に戻し、エラーを表示する。
- **UI-04** 設定画面：表示名の変更、アーカイブした習慣の一覧、ログアウト。

## 9. ルーム

### 9.1 基本

- **ROOM-01** [確定] 1ルーム1習慣。メンバー全員が同じ習慣に取り組む。
- **ROOM-02** ルームの習慣の名前・アイコン・色はオーナーが決める。
  - 要件で決めたのは名前だけ。アイコンと色もオーナーが決める形にしたのは [暫定]
- **ROOM-03** オーナーが名前・アイコン・色を変更すると、参加中のメンバー全員の習慣に反映する。
- **ROOM-04** [確定] 実施する曜日は、メンバーがそれぞれ自分で決める（参加時に選び、後で変更できる）。
- **ROOM-05** メンバーが変更できるのは、自分の曜日だけ。名前・アイコン・色は変更できない。
- **ROOM-06** [確定] ルームの習慣は、各メンバーの10個の上限（HABIT-01）に数える。上限に達している人は参加もルームの作成もできない。
- **ROOM-07** [暫定] 1ルームの最大人数は10人。
- **ROOM-08** 記録はルームに参加した日から数える（参加日 = その習慣の `start_date`）。
- **ROOM-09** 実装方式：ルームの習慣は、メンバーごとに `habits` の行を1つ持つ（`habits.room_id` で結びつく）。このため、スタンプ・連続・カレンダーは個人の習慣と同じ処理で扱える。
- **ROOM-10** ルームの習慣は、参加中は直接アーカイブも削除もできない。やめるときは退出する（ROOM-30）。退出した後は削除できる。

### 9.2 招待と参加

- **ROOM-20** [確定] オーナーが招待URL（`/join/<token>`）を発行し、LINEなどで送る。
  - オーナーの画面には「URLを送る」（Web Share API。使えない端末ではコピー）と「コピー」がある
  - 招待URLはオーナーだけに表示する
- **ROOM-21** [確定] 招待URLに有効期限はない。オーナーが作り直すと、古いURLは使えなくなる。
- **ROOM-22** 招待URLを開いたときの流れ：
  1. 未ログインならログイン画面へ（ログイン画面に「招待されています」と表示）
  2. 表示名がまだ登録されていなければ表示名の登録画面へ
  3. 招待画面へ戻る。ルーム名・オーナー名・参加人数が表示される
  4. 自分の曜日を選んで参加する
- **ROOM-23** 招待画面では状態ごとに表示を分ける：
  - 参加できる
  - すでにメンバー → ルーム画面へ移動
  - 満員
  - 外された人（参加不可）
  - 無効なURL（作り直し前のURL、または削除されたルーム）
  - 習慣が10個ある（参加不可。どれかをアーカイブするよう案内する）

### 9.3 ルーム画面

- **ROOM-40** 自分のスタンプボタン（ホームと同じカード）。
- **ROOM-41** [確定] メンバー一覧（参加日順）。各メンバーについて表示するもの：
  - 表示名（オーナーと自分には印を付ける）
  - 曜日
  - 現在の連続、累計
  - 今日の状況：✅（押した）／⬜ まだ（実施日で未スタンプ）／お休み（実施日でなく未スタンプ）
- **ROOM-42** [確定] メンバーをタップすると、その人のカレンダー（閲覧のみ）が見られる。自分をタップしたら自分の習慣の詳細へ移動する。
- **ROOM-43** [確定] 👏リアクション：
  - 他のメンバーのスタンプに👏を送れる。もう一度押すと取り消せる
  - 1つのスタンプに1人1回まで
  - 自分のスタンプには送れない
  - 送れる場所：ルーム画面の今日のスタンプ、メンバーのカレンダーのスタンプ
  - もらった数は自分のカレンダーにも出る
  - スタンプを取り消すと、そのスタンプへの👏も消える
- **ROOM-44** [確定] 全員達成カレンダー：全員達成の日に🎉を付ける。
  - 判定（`src/lib/room-stats.ts` の `allDoneDates`）：その日を実施日とするメンバー（参加日以降）を集める。1人以上いて、全員がスタンプを押していれば全員達成
  - 実施日のメンバーが0人の日は対象外
  - 判定に含めるのは、今参加しているメンバーだけ
- **ROOM-45** [確定] ランキングは作らない。

### 9.4 退出・オーナーの引き継ぎ・メンバーを外す・ルームの削除

- **ROOM-30** [確定] メンバーはいつでも退出できる。退出すると：
  - その人のルームの習慣はアーカイブになる（記録は残り、閲覧のみ）
  - メンバー一覧から消える
- **ROOM-31** [暫定] 自分で退出した人は、招待URLから再参加できる。
  - 再参加すると同じ習慣のアーカイブが解除され、以前の記録を引き継ぐ（開始日はもとのまま）
  - 再参加には10個の上限に空きが必要
- **ROOM-32** [確定] オーナーが退出するときは、次のオーナーを今のメンバーから選ぶ。
  - 選択肢の初期値は、参加日が一番古いメンバー [暫定]
- **ROOM-33** オーナーのほかにメンバーがいない場合、オーナーの退出はルームの削除（ROOM-35）と同じ扱いにする。確認ダイアログを出す。
- **ROOM-34** [確定] オーナーだけが、ほかのメンバーをルームから外せる。確認ダイアログを出す。
  - 外された人の習慣はアーカイブになる（記録は本人の手元に残る）
  - 外された人は、招待URLが作り直されても再参加できない [暫定]
- **ROOM-35** [確定] オーナーだけがルームを削除できる。確認ダイアログを出す。
  - 削除すると、全メンバーのルームの習慣がアーカイブになり、記録はそれぞれの手元に残る [暫定]
  - 招待URLは使えなくなる
  - ルームの行は消さずに `deleted_at` を設定する（論理削除）

## 10. 見える範囲（プライバシー）

- **PRIV-01** 個人の習慣・そのスタンプ・曜日設定は、本人しか見られない。
- **PRIV-02** ルームの習慣・そのスタンプ・曜日設定・👏は、そのルームに今参加しているメンバーだけが見られる。
- **PRIV-03** 他人のプロフィールで見られるのは表示名だけ。それも同じルームに参加している人の分だけ。メールアドレスは見せない。
- **PRIV-04** 退出した人・外された人の習慣は、ルームの他のメンバーから見えなくなる。
- **PRIV-05** PRIV-01〜04 は、すべてのテーブルで Supabase の行単位アクセス制御（RLS）によって強制する。画面だけで隠すのは不可。

## 11. 非機能要件

| ID | 項目 | 内容 |
|---|---|---|
| NFR-01 | 端末 | スマホ縦向きを基本にする。PCでも崩れずに表示する |
| NFR-02 | PWA | manifest とアイコンを用意し、ホーム画面に追加して全画面で使えるようにする |
| NFR-03 | ダークモード | 端末の設定に合わせる |
| NFR-04 | 通知 | [確定] 初期版では作らない |
| NFR-05 | 費用 | [確定] 無料枠（Supabase Free、Vercel Hobby）で運用する |
| NFR-06 | 規模 | 数人規模。集計を毎回計算しても性能上の問題はない前提 |

## 12. 技術構成

| 層 | 採用技術 |
|---|---|
| フロントエンド | Next.js 16（App Router）、React 19、TypeScript、Tailwind CSS 4 |
| 認証 | Supabase Auth（Googleのみ） |
| データベース | Supabase（PostgreSQL）＋ RLS |

## 13. データモデル

```
profiles
  id uuid PK = auth.users.id
  display_name text (1..30)
  onboarded boolean               -- 表示名を登録済みか
  created_at

habits
  id uuid PK
  user_id uuid → profiles
  room_id uuid NULL → rooms       -- NULL なら個人の習慣
  name text (1..30), icon text, color text (6色のどれか)
  start_date date                 -- 作成日 / ルーム参加日。変更不可
  archived_at timestamptz NULL
  created_at

habit_schedules                   -- 曜日設定の履歴
  id, habit_id → habits
  weekdays smallint[]             -- 0..6、1つ以上、重複なしで昇順
  valid_from date
  UNIQUE (habit_id, valid_from)

stamps
  id, habit_id → habits
  date date                       -- 午前3時区切りの日付
  stamped_at timestamptz          -- サーバーが設定
  is_late boolean                 -- サーバーが設定（date <> 今日）
  UNIQUE (habit_id, date)

rooms
  id, name, icon, color
  owner_id → profiles
  invite_token text UNIQUE        -- 推測できない32桁の16進数
  created_at, deleted_at NULL     -- 論理削除

room_members
  PK (room_id, user_id)
  habit_id → habits               -- この人のルームの習慣
  joined_at
  left_at NULL, left_reason NULL ('left' | 'removed' | 'room_deleted')

reactions                         -- 👏
  PK (stamp_id, user_id)
  stamp_id → stamps (スタンプを消すと一緒に消える)
  user_id → profiles
  created_at
```

DB側で強制していること：
- 習慣の上限10個（トリガー）
- 習慣の `user_id`・`start_date`・`room_id` は変更不可（トリガー）
- ルームの習慣の名前・アイコン・色・アーカイブ状態は、ルーム操作の関数の中からしか変えられない（トリガー＋関数内だけで有効になるフラグ）
- スタンプを押せる期間（RLS）

## 14. サーバー関数（Supabase RPC）

複数の表をまとめて書き換える操作は、すべて `security definer` の関数で行う。ルーム関連のテーブルには、クライアントから直接書き込ませない。

| 関数 | 誰が呼べるか | 動作 |
|---|---|---|
| `create_habit(name, icon, color, weekdays)` | ログイン中の人 | 個人の習慣と、今日からの曜日設定を作る |
| `update_habit(habit_id, name, icon, color, weekdays)` | 習慣の持ち主 | 個人の習慣なら名前などを変える（ルームの習慣は無視）。曜日が変わっていれば今日から新しい設定を追加する |
| `create_room(name, icon, color, weekdays)` | ログイン中の人 | ルーム、作成者の習慣、メンバー行を作る |
| `get_invite(token)` | ログイン中の人 | 招待画面用の情報と状態（`ok` / `member` / `full` / `removed` / `not_found`）を返す |
| `join_room(token, weekdays)` | ログイン中の人 | 参加する。退出したことがある人は同じ習慣を戻す。外された人・満員・無効なURLはエラー |
| `leave_room(room_id, new_owner?)` | メンバー | 退出する。オーナーは `new_owner` が必須。ほかにメンバーがいなければルームを削除する |
| `remove_member(room_id, user_id)` | オーナー | メンバーを外す |
| `delete_room(room_id)` | オーナー | 全員を退出させ、ルームを論理削除する |
| `update_room(room_id, name, icon, color)` | オーナー | ルームを変更し、参加中のメンバーの習慣にも反映する |
| `regenerate_invite(room_id)` | オーナー | 招待URLの token を作り直す |

画面に出すエラーの種類（例外メッセージ）：`habit_limit_reached`, `room_full`, `removed_from_room`, `invite_not_found`, `new_owner_required`, `not_room_owner`, `not_room_member`, `habit_not_found`, `room_habit_managed_by_room`

## 17. 気づいている課題

- **ISSUE-01** 月初めは「過去7日」が前の月にかかる。そのため、押し忘れを後から押すにはカレンダーで前の月に移動する必要がある。改善案：ホームに直近7日分を並べて表示する。
- **ISSUE-02** Supabase の無料プランは、1週間アクセスがないとプロジェクトが一時停止する。
